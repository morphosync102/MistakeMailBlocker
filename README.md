# Gmail誤送信防止 Chrome拡張機能（個人用）

Gmailでのメール送信時に、独自の確認モーダルを表示して誤送信を防止するChrome拡張機能です。
元々は企業向けに開発されたものを、個人での利用に最適化（全宛先チェック、誤送信防止機能の強化）しました。

## システム概要

Gmailの「送信」ボタンクリックを検知して一時停止し、以下の3段階のチェックを経てメールを送信します。
特に「慣れによる惰性的なクリック」を防ぐため、送信コード入力や最終確認画面など、意図的に送信完了までのハードルを設けています。

### 主な機能

1.  **全宛先チェック**: 送信先に関わらず、すべてのメールに対してチェックを行います。
2.  **独自の警告ロジック**:
    *   **添付ファイルチェック**: 「添付」という言葉があるのにファイルがない場合の警告や、ZIPファイル添付時にはパスワード設定の確認を促します。
    *   **件名チェック**: 件名が空の場合に警告します。
    *   **送信元チェック**: どのアドレスから送信しようとしているかを明示し、誤ったアカウントからの送信を防ぎます。
3.  **4桁のセキュリティコード**: 送信前にランダム生成された4桁のコード入力を強制し、無意識の送信を防止します。
4.  **最終確認モーダル**: コード入力後にも、さらに警告マーク付きの最終確認画面を表示します。

## UIフロー

送信ボタンを押すと、以下の順でモーダルが表示されます。

1.  **チェック画面 (CheckModal)**
    *   送信元、宛先、件名、添付ファイルの状態を一覧表示。
    *   「注意」項目がある場合、チェックボックスによる確認が必須となります。
    *   問題なければ「次へ」ボタンが有効になります。

2.  **確認画面 & コード入力 (ConfirmModal)**
    *   メール本文の行数やプレビュー、宛先一覧を表示。
    *   画面内に表示された「送信コード（4桁の数字）」の入力が必須です。
    *   コードが一致して初めて「次へ」ボタンが押せるようになります。

3.  **最終確認画面 (FinalConfirmModal)**
    *   警告アイコンと共に「本当に送信してよろしいですか？」というメッセージを表示。
    *   この画面で「送信する」を押すことで、初めてGmailの実際の送信処理が実行されます。

## 技術スタック

Chrome拡張機能としてモダンなWeb技術を使用して開発されています。

*   **言語**: [TypeScript](https://www.typescriptlang.org/) (型安全性と可読性の向上)
*   **UIフレームワーク**: [React](https://react.dev/) (コンポーネントベースのUI構築)
*   **ビルドツール**: [Vite](https://vitejs.dev/) (高速な開発サーバーとビルド)
*   **スタイリング**: [TailwindCSS](https://tailwindcss.com/) (効率的なスタイリング)

## インストール方法

### 1. ビルド

```bash
npm install
npm run build
```

### 2. Chrome拡張機能として読み込み

1.  Chromeで `chrome://extensions/` を開く
2.  右上の「デベロッパーモード」を有効にする
3.  「パッケージ化されていない拡張機能を読み込む」をクリック
4.  プロジェクトの `dist` フォルダを選択

> **注意**: 拡張機能のアイコンが表示されない、または更新が反映されない場合は、拡張機能管理画面のリロードボタンを押すか、一度削除して読み込み直してください。

## 開発・カスタマイズ

### 開発モード
`npm run dev` でファイル変更を監視して自動的に再ビルドされます。

### ファイル構成
*   `src/content/`: Gmailページ内で動作するメインスクリプト
*   `src/components/`: Reactコンポーネント（モーダル等）
*   `src/gmailScraper.ts`: GmailのDOMから情報を取得するロジック
*   `src/validator.ts`: メールの内容を判定するロジック

## 注意事項

*   この拡張機能はGmailのDOM構造（HTMLのクラス名や属性）に依存しています。Gmailの仕様変更により、宛先が取得できなくなったり、ボタンが検知できなくなる可能性があります。
